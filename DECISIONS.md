# Design decisions

The decisions behind sysprobe, each with its reason and what it costs if it
turns out to be wrong. Format: `- <what> — <why> — <cost if wrong>`.

## Kernel side

- aggregate syscall and run-queue latency into per-CPU log2 histograms in the kernel; stream only TCP events through a ring buffer — syscalls and context switches run at millions per second, so per-event streaming would dominate the cost; connects and retransmits are rare and benefit from per-event detail (addresses, pid, latency) — if per-event syscall detail were needed (e.g. arguments), a sampling ring-buffer path would have to be added.
- attach the syscall programs as raw tracepoints on `sys_enter`/`sys_exit` rather than classic `raw_syscalls:*` tracepoints — same tracepoints, but raw attachment needs neither tracefs nor BTF and skips building the classic record — if the classic tracepoint API is ever required, it is a two-line SEC/attach change; the in-tree measurement showed little difference between the two (about +192 ns vs +190 ns in the VM).
- use `tp_btf` with minimal CO-RE type declarations (`bpf/core_types.h`) instead of a generated `vmlinux.h` or classic tracepoint structs for scheduler and TCP — the classic `tcp_retransmit_skb` record changed layout in 6.x (the linuxkit 7.0 kernel has an `err` field and a separate event class), and a committed `vmlinux.h` is 3 MB of one kernel's types — requires kernel BTF for `runq` and `tcp` (documented; `syscalls` still works without it).
- rewrite LRU start slots in place and invalidate (`ts = 0`) instead of update+delete — LRU updates allocate and swap an element; measured during development as roughly halving the added cost (+400 ns to +190 ns per getppid in the VM) — a stale slot can only be misread if a thread's exit is missed and its tid is reused before its next enter, which the enter path overwrites anyway.
- per-CPU hash with `BPF_F_NO_PREALLOC` for histograms — preallocation would reserve keys × CPUs × 320 B up front (42 MB on 8 CPUs, far more on large hosts) — insertions can fail under bursts of new keys; counted as `hist_insert_failed` (0 to 111 per ~10 s integration run observed).
- 36 log2 buckets (1 ns .. ~34 s, last open-ended) — covers sub-microsecond syscalls to multi-second blocking waits with 288 bytes of buckets; quantile error bounded by 2x — finer resolution would need more buckets or a log-linear layout.
- garbage-collect exited processes from `sched_process_exit`, reading the exited set before the histogram maps — independent of PID namespaces (a /proc scan inside a container would see every host pid as dead) and loses no final values — a thread that outlives its group leader re-creates keys and appears as a new process with the same pid.
- name processes by `proc_comm` (set at exec and when the group leader creates a key), else the most frequent per-key comm — the first recordings showed worker thread names and pre-exec parent names fragmenting one process into several labels — deltas before an exec stay under the old name (by design: that work was done by the old program).
- retransmit events carry tgid 0 — they fire from the retransmit timer in softirq context, where "current" is unrelated — per-process retransmit attribution would need a socket-to-pid map; deferred.
- BPF programs licensed `Dual MIT/GPL` (SPDX `GPL-2.0-only OR MIT`) — GPL-compatible license strings are required by the kernel for the helpers used; the repo is MIT — none expected.

## Userspace

- the snapshot stream (`events.Snapshot`) is the unit of recording, replay and testing — one boundary makes live, replay and test identical below the probe — fixtures are cumulative per snapshot and so larger than pure deltas (largest committed: 754 KB).
- reset detection treats any decreasing bucket, count or sum as a new series and uses the reading itself as the delta — exact when the key was re-created right after the previous read, otherwise undercounts by at most one interval — a counter that wrapped u64 would also look like a reset (not reachable in practice).
- a live process evicted over `MaxProcesses` leaves a one-snapshot tombstone of its last kernel readings; when the tgid is seen again its series difference against the tombstone (added after a test exposed double-counted comm totals) — the kernel maps keep its cumulative histograms after userspace evicts it, so differencing against zero re-added its whole history to the comm counters every interval (reproduced: 180 calls exported for 120 real). Chosen over "evict only exited processes" because that would leave the process map unbounded by the cap — tombstones cost up to one histogram (304 B) per evicted series for one snapshot, bounded by the kernel map sizes (16384 syscall keys, 8192 runq tgids, about 7.5 MB worst case); per-pid series and the top view still restart from zero for a returning process, and a process evicted on every snapshot never appears in the top view.
- default Prometheus labels are `comm` (plus `syscall`), with first-come sticky admission of 256 comms and 64 TCP destinations before folding into `other` — per-pid labels make cardinality unbounded on busy hosts and series vanish on exit; sticky admission keeps every counter monotonic — two different programs with the same comm share series; `-prom-labels pid` exists for when that matters.
- export bucket edges at `2^k` ns, k = 10, 12 .. 34 — the kernel's own edges, so no interpolation error; 13 buckets is a typical Prometheus budget — sub-microsecond detail is only in the top view.
- the top view is a hand-rolled ANSI renderer over `golang.org/x/term`, not a TUI framework — a pure `Render(View) string` is golden-testable and keeps dependencies to cilium/ebpf, client_golang and x/term — fewer interactive features (no scrolling, mouse).
- `IN-SYS` (summed syscall time per wall second) is the default sort — it ranks "who is waiting on the kernel" — blocking syscalls (futex, epoll) dominate it; `-sort rate|p99|runq|pid` are available.
- sysprobe excludes its own pid in the kernel by default (`-include-self` to disable) — avoids observing its own map reads — only matches when sysprobe shares the PID namespace with the kernel's view (documented: run with `--pid=host`).

## Build, test and data

- commit the bpf2go-generated `*_bpfel.go`/`.o` and rebuild them in a pinned `golang:1.27.1-trixie` image with Debian clang 19.1.7 — macOS clang has no BPF target, and committed objects let `make check` build anywhere without clang or Docker — reproducibility is checked twice: the rebuild is byte-identical on arm64 locally, and CI's `bpf` job rebuilds the objects on amd64 and fails on any byte difference, which also catches drift after a Debian clang update.
- syscall name tables generated from `ausyscall --dump` (auditd 4.0.2 in the builder) for both x86_64 and aarch64 — one tool gives both architectures independent of host — syscalls newer than auditd's table show as `syscall_<nr>`.
- the load generator uses `clock_nanosleep` for the timed workload — the first integration run failed because the Go runtime's own `nanosleep` calls (runtime.usleep) were mixed into the count; the runtime never calls `clock_nanosleep` — none; the verifier now asserts an exact count range.
- the integration test verifies semantics against workload ground truth (exact sleep count range, mean >= requested sleep, p50 in the right log2 bucket, exact connect/refused counts, retransmits towards the overflowing listener) and writes that ground truth next to the recording, so the same `Verify` runs offline in `make check` — proves the committed fixtures are not just parseable but correct; `TestVerifyDetectsWrongExpectations` proves `Verify` is not vacuous — the bounds are loose enough for a noisy VM (mean <= 2x the sleep).
- provoke SYN retransmits with a backlog-0 listener that never accepts — once the accept queue is full the kernel drops new SYNs, so the client retransmits; no iptables/netem or extra privileges needed — relies on default `tcp_abort_on_overflow=0`.
- overhead measured with `getppid()` medians inside the integration container — cheapest syscall gives the probe's fixed cost; medians of 7 runs damp VM noise — VM numbers do not transfer to bare metal; stated wherever quoted.
- keep other containers' processes in the committed recordings — they are what a real host looks like and only expose comm names, pids and loopback ports — names such as `nginx`, `auth` and `.postgres-wrapp` from unrelated local containers appear in the fixtures (noted in DATA.md).
- coverage gate (80%) over the 12 packages that run without a kernel; `internal/probe` and the `cmd` mains are excluded — the probe can only run privileged on Linux and is covered by `make integration` instead — probe regressions surface only in the integration job.
- `.golangci.yml` excludes `fmt.Fprint*` from errcheck — those calls write terminal/report output where a write error is not actionable — a failing stdout would go unnoticed.
- no `.env.example` — sysprobe reads no environment variables (configuration is flags only); `SYSPROBE_RECORD_DIR`/`SYSPROBE_WHERE` are test-harness inputs documented in `scripts/integration.sh` — none.
